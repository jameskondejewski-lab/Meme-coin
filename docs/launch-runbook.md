# Launch runbook

Every token moves through these stages in order. **No stage is skipped, and mainnet is only ever run after the project owner explicitly approves it.**

| Stage | Command | Gate to pass before the next stage |
|---|---|---|
| 1. Spec review | edit `tokens/<name>.json` | Name/ticker collision check done; allocations and supply agreed; metadata JSON + image hosted (mainnet) |
| 2. Unit tests | `npm test` | All green |
| 3. Localnet | `solana-test-validator` + `npm run launch -- --spec … --cluster localnet --airdrop` | Verification PASSED (15 checks) **and** `scripts/adversarial-check.sh` passes |
| 4. Devnet | `npm run launch -- --spec … --cluster devnet` (fund the payer via faucet.solana.com) | Verification PASSED on a public cluster; token visible on Explorer/Solscan (devnet); adversarial check against devnet RPC |
| 5. Security review | `npm run snapshot -- --mint <devnet mint>`, manual review of the deployment record | No findings; spec hash in record matches the reviewed spec |
| 6. Mainnet | `npm run launch -- --spec … --cluster mainnet-beta --keypair <file> --confirm-mainnet <SYMBOL>` | **Owner approval in writing.** Dry run first (`--dry-run`). |
| 7. Post-launch | `npm run snapshot -- --mint <mint>` + RugCheck/Solscan | Authorities null, supply fixed, metadata immutable, as recorded |

## What the launcher guarantees (enforced in code and verified on-chain)

- **Token-2022 mint with only two extensions:** MetadataPointer (pointing at the mint, no authority) and TokenMetadata.
- **None of the extensions scanners flag:** no transfer fee, transfer hook, permanent delegate, pausable, default-frozen state, confidential transfers or non-transferable.
- **No freeze authority, ever.** The mint is initialised without one.
- **Fixed supply.** The mint authority is revoked in the same transaction that mints the supply.
- **Immutable metadata** by default. The update authority is removed in the same transaction.
- **One atomic transaction.** There is never a confirmed state with supply minted and the authority still live. The test token's launch transaction was 662 of 1,232 bytes.
- **Simulated before sending.** Signatures are verified during simulation.
- **Keys:** payer keys live outside the repo (`~/.config/solana-launch-intel/`, mode 0600) and paths inside the repo are refused. Mainnet keys are never generated by the tool.
- **Mainnet requires** an explicit `--keypair` and `--confirm-mainnet <SYMBOL>` matching the spec.
- **Deployment record** (`deployments/<cluster>/<SYMBOL>-<mint>.json`) stores the spec, spec hash, signature, every verification check and the pinned SDK versions.

## Adversarial check (stage 3/4)

`scripts/adversarial-check.sh <MINT> <PAYER_KEYPAIR> [RPC]` uses the independent Agave `spl-token` CLI to attack the token with the original payer key:

- mint more supply
- freeze a holder
- rename via metadata
- re-point the metadata

Every attack must be rejected. A normal transfer must still work.

**Negative control:** on a deliberately unsafe token (created with mint and freeze authority kept), the script reports 5 failures and exits non-zero, and the safety scanner rates the token `red-flags`.

## Not done yet — required before mainnet

These are open decisions, and each one is the owner's call:

1. **Concept, name and ticker**, with a collision check against Jupiter, DexScreener and CoinGecko.
2. **Hosted metadata JSON and image.** Use permanent storage (Arweave or IPFS), not a mutable web server; the metadata itself will be immutable.
3. **Distribution and liquidity plan:**
   - where liquidity is added (Raydium CPMM with Burn & Earn, or Meteora DAMM v2 with `permanent_lock_position`);
   - how much SOL is paired;
   - any team allocation, which should be vested in Jupiter Lock and disclosed.
   - This toolkit does not add liquidity yet.
4. **Signing.** Ideally a hardware wallet or a Squads v4 vault. The current CLI signs with a keypair file, which is acceptable only for a single-use launch wallet funded with just the launch cost.
5. **Priority fees and compute-budget instructions** for mainnet congestion. Not added yet.
6. **Legal review.** Holder-reward, fee-sharing and stock-paired designs in particular may change the securities analysis.
